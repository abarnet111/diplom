# Дипломная работа по профессии «Системный администратор»
## Тема: Разработка отказоустойчивой инфраструктуры для сайта в Yandex Cloud

### 1. Введение

#### 1.1. Цель работы
Разработать и развернуть отказоустойчивую инфраструктуру для статического сайта в облаке Yandex Cloud. Инфраструктура должна включать в себя системы мониторинга, централизованного сбора логов и резервного копирования, а также соответствовать базовым стандартам безопасности.

#### 1.2. Используемые инструменты и технологии
*   **Облачная платформа:** Yandex Cloud
*   **Управление инфраструктурой (IaC):** Terraform
*   **Управление конфигурациями:** Ansible
*   **Система контроля версий:** Git, GitHub
*   **Операционная система:** Ubuntu
*   **Мониторинг:** Zabbix
*   **Сбор и анализ логов:** Elastic Stack (Elasticsearch, Kibana, Filebeat)
*   **Веб-сервер:** Nginx
*   **Сетевое взаимодействие:** Бастион-хост (Jump host), NAT-шлюз

### 2. Проектирование и архитектура

#### 2.1. Принятые решения и компромиссы
*   **Разделение ответственности Terraform и Ansible:** Terraform используется исключительно для создания первичной инфраструктуры (виртуальные машины, сети, балансировщик).
*   Ansible отвечает за настройку всего ПО на уже созданных серверах (nginx, Zabbix-агенты, Filebeat). Это позволяет переиспользовать Ansible-плейбуки даже при пересоздании инфраструктуры.
*   **Прерываемые ВМ:** Для экономии ресурсов все виртуальные машины созданы как прерываемые (с 20% гарантией CPU). Перед итоговой демонстрацией они были переведены в обычный режим работы, как того требует задание.
*   **Использование Docker для ELK:** В связи с известными трудностями доступа к официальным репозиториям Elastic, было принято решение развернуть Elasticsearch и Kibana в Docker-контейнерах на отдельных ВМ. Это обеспечило стабильность и простоту установки, не привязываясь к внешним репозиториям.
* 
#### 2.2. Сетевая архитектура
*   Создана одна VPC сеть `diplom-network`.
*   Выделены **публичная подсеть** (`public-ru-central1-a`) и две **приватные подсети** (`private-ru-central1-a`, `private-ru-central1-b`) для обеспечения отказоустойчивости.
*   Для доступа ВМ в приватных подсетях в интернет (для обновлений) настроен **NAT-шлюз** и таблица маршрутизации.
*   Для доступа администратора к ВМ в приватных подсетях используется **бастион-хост** (jump host) с публичным IP-адресом.

#### 2.3. Распределение сервисов по подсетям
*   **Публичная подсеть:**
    *   Бастион-хост (`bastion`)
    *   Балансировщик нагрузки (`web-load-balancer`) - слушает входящий трафик
    *   Zabbix-сервер (`zabbix`)
    *   Kibana (`kibana`)
*   **Приватная подсеть А (ru-central1-a):**
    *   Веб-сервер 1 (`web1`)
    *   Elasticsearch (`elasticsearch`)
*   **Приватная подсеть Б (ru-central1-b):**
    *   Веб-сервер 2 (`web2`)

### 3. Реализация проекта

#### 3.1. Подготовка окружения
1.  **Сервисный аккаунт:** В Yandex Cloud создан сервисный аккаунт `diplom-sa` с ролью `editor` и для него сгенерирован авторизованный ключ (файл `authorized_key.json`).
    Файл ключа хранится локально и внесён в `.gitignore` для безопасности.
3.  **SSH-ключи:** Сгенерирована пара SSH-ключей для доступа к ВМ. Публичный ключ (`id_rsa.pub`) копируется в метаданные ВМ при создании через Terraform.

#### 3.2. Управление инфраструктурой (Terraform)
Код Terraform разделён на логические файлы для удобства чтения и поддержки:
*   `providers.tf` - настройка провайдера Yandex Cloud.
*   `variables.tf`, `outputs.tf` - переменные и выходные данные.
*   `network.tf` - создание VPC, подсетей, NAT-шлюза, таблиц маршрутизации.
*   `bastion.tf` - создание jump host.
*   `web-servers.tf` - создание двух ВМ `web1` и `web2`.
*   `load-balancer.tf` - настройка целевой группы, бэкенд-группы, HTTP-роутера и Application Load Balancer.
*   `zabbix.tf`, `elasticsearch.tf`, `kibana.tf`, `backups.tf` - создание соответствующих ВМ и ресурсов.
### 3.3. Управление конфигурациями (Ansible)

Управляющий узел развернут непосредственно на бастион-хосте (bastion).
Ansible-плейбуки пишутся на бастионе и оттуда же запускаются, используя
внутренние FQDN имена.

### 3.4. Установка и настройка сервисов

- **Nginx:** Установлен на web1 и web2 через Ansible. На каждой ВМ создана своя индексная страница с именем хоста для наглядности работы балансировщика.

- **Балансировщик:** Создан Application Load Balancer с публичным IP. Настроена проверка здоровья на порт 80. Трафик распределяется между web1 и web2.

- **Zabbix:**
  - Zabbix-сервер установлен на выделенной ВМ в публичной подсети. В качестве базы данных используется MySQL. Веб-интерфейс доступен по адресу `http://<zabbix_public_ip>/zabbix`.
  - Zabbix-агенты установлены на web1 и web2 через Ansible и настроены на отправку данных на внутренний IP Zabbix-сервера.
  - В Zabbix создан дашборд, отображающий ключевые метрики (загрузка CPU, LA, использование памяти и диска). Настроены триггеры для оповещения о превышении порогов.

- **Сбор логов (Elastic Stack):**
  - **Elasticsearch:** Запущен в Docker-контейнере на отдельной ВМ в приватной подсети.
  - **Kibana:** Запущена в Docker-контейнере на отдельной ВМ в публичной подсети. Веб-интерфейс доступен по адресу `http://<kibana_public_ip>:5601`.
  - **Filebeat:** Установлен на web1 и web2 через Ansible. Настроен на чтение логов `access.log` и `error.log` Nginx и отправку их в Elasticsearch.

- **Резервное копирование:**
  - Через Terraform создано расписание снапшотов (snapshot schedule) для дисков всех ВМ.
  - Параметры расписания: ежедневно в 00:00, срок хранения — 7 дней.
